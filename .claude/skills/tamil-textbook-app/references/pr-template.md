# PR 本文の型

前例：PR #33「v4.9-preview: 実践パック（フレーズ120文＋ドリル100問）、読みの統一、下部ナビ修正」。

タイトル：`vX.Y-stage: 変更1（規模）、変更2、変更3`

```markdown
（一文：何を足し・直し、何を変えていないか。例：本課20課のデータを一切変えずに、…）

## 1. （変更1）

- **要点**（数・場所）— 何ができるようになるか
- 仕組み（どのファイルが何を保証するか。生成物ならその作り方）
- 状態（機械検査済み・ネイティブ監査待ち、review / confidence の値）。根拠は `（監査記録）`

## 2. （変更2）

- 何が起きていたか（件数と具体例）
- どの規則で直したか（多数決ではなく規則から）
- 変更の範囲（表示層◯行のみ。`targetTamil` `ttsText` `meaningJa`、問題文、正答、進捗キーは不変）

## 3. 使いやすさ（UI を触った場合）

- 不具合の原因（どの指定が何を上書きしていたか）と修正、再現・修正を確認した環境

## 検査

- 追加・変更したスイートと、CI への登録
- 全 N スイート green（ローカル）
- 390px 幅の Chromium で通し操作、コンソールエラー 0・横スクロール 0

## ネイティブ確認待ち（マージ後も未承認のまま）

- （項目）
- （反転できる既定と、反転のしかた）
```

- 本文の末尾には、その環境の決まりどおりの生成元表記を付ける。
- マージは利用者の明示の了承を得てから（main へのマージ＝公開）。
